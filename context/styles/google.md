#### Google developer documentation style

Follow the Google developer documentation style guide, as it applies to a note.

- Use the present tense. Write "the worker retries", not "the worker will retry", unless the event is still to come.
- Use the active voice, and make clear who does the action.
- Address the reader as "you", not "we" or "the user", when you tell them what to do.
- Write the titles and headings you choose in sentence case.
- Put code, commands, file names, paths and property names in code font (backticks).
- Do not write "please", "simply", "easily" or "obviously". Do not use Latin abbreviations: write "for example", not "e.g.", and "that is", not "i.e.".
- Use contractions where they read naturally, such as "doesn't" and "can't".
- Write "and" or "or", not "and/or", and use the serial comma.
