#### ASD-STE100 (Simplified Technical English)

Write each sentence so that a reader understands it on the first read, also in a second language.

- Use one word for one meaning. Use the same word for the same thing in the whole note. If the code says "lease", do not write "grant" two lines later.
- Use technical names freely: identifiers, file names, commands and project terms. Put identifiers in backticks.
- Use short, common words. Write "use", not "utilize", and "before", not "prior to".
- Do not use an "-ing" word as a verb or an adjective. Write "when the worker restarts", not "by restarting the worker". A technical name or a noun such as "during" is correct.
- Use one verb, not a phrasal verb. Write "start", not "set up", and "do", not "carry out".
- Keep a noun cluster to three words or fewer.
- Use the active voice, so that each sentence names who or what does the action. Use the passive only when the actor is unknown or does not matter.
- Use simple tenses: the present, the simple past and the simple future.
- State facts and rules with direct verbs: "can", "must" and "do not". Do not hedge with "would", "might" or "should".
- Write one idea in each sentence. Keep a descriptive sentence to 25 words or fewer, and an instruction to 20 words or fewer.
- Write an instruction as a command, with one instruction in each sentence. Put a condition before its instruction: "If the build fails, read the first error."
- Do not join two sentences with a semicolon. Keep the articles ("a", "an", "the"). Do not write in telegraph style.
- Give each paragraph one topic and six sentences or fewer. Make each list item a full sentence.
- Start a warning with a command. Give the reason in the next sentence.
